# 圣杯搜索协议 ARCH-SEARCH v0.1

## 0. 为什么不再 import 现有架构

HRM / LFM2 / TokenFormer / TTT / MoD 都是已知解的变体。r042 的负结果
（同 D 追平 dense 但 3x per-token FLOPs）已经说明：在 28M/0.1B 尺度，
"把已知机制换一种组合"买不到奇迹。

真正要找的是：**在 per-token FLOPs = 60M dense、训练前向 = 推理前向的
约束下，能显著降低 (A,B,E) 或改变 (alpha,beta) 的未知计算结构。**

## 1. 搜索方式：微架构合成，而不是手工设计

- 任务分布：SPEC 的 P1-P4 合成探针 + 0.1B 语料 CE。
  - P2/P3：复制、联想召回、induction head、层次状态追踪、迭代复合；
  - P1：可控 bit 知识注入；
  - P4：干净 holdout BPB。
- 搜索粒度：**token-mixing cell 与 memory cell 的程序图**，不是整网。
- 评价：**单位 FLOPs 的任务能力**（accuracy / loss 下降），不是绝对精度。
- 方法：随机程序生成 + 锦标赛/进化 + 预注册 kill gate。
- 预算：单个候选 <=10M 参数、<=5M tokens、<=5 分钟（M4 实测约 30-60k
  tokens/s）；每轮 20-40 个候选，一晚可跑 2-3 轮。

## 2. 初始搜索空间（原语基因，不是架构）

每个 cell 是这些原语的有向无环组合：

1. 精确注意力通路（MLA，仅少数层保留，对应 B4）
2. 线性注意力 / delta-rule / 快速权重（序列记忆）
3. 1D 卷积 / FFT + 频率门（局部与谱混合）
4. 低秩因子矩阵 U diag(g) V，g 由 layer_embed 生成（生成式权重）
5. 块对角 / Monarch / 蝴蝶矩阵 + 可学习置换（结构化稀疏）
6. token 条件路由（top-k 原子选择，激活 FLOPs 固定）
7. 门控残差 / 乘法交互 / 双线性项
8. 跨层状态 z_L/z_H（但只作候选基因，不再作主架构）

## 3. 为什么这有可能找到圣杯

固定 active FLOPs 后，唯一能赢的路径是：**同样的 FLOPs 构造出更适配
语言结构的函数**。合成探针能给出清晰的因果信号（哪个原语解决哪类
B1-B4 缺口），避免整网训练把机制贡献淹没在噪声里。

## 4. 判定与交付

- 任何 cell 在 FLOPs-normalized 探针上超过注意力 >=3x，进入 28M/0.1B
  整网验证；
- 否则记录否定证据与缺口分解；
- 最终交付：被搜索发现的 cell 图 + Viby 实现 + 缩放律常数对比。

## 5. 与当前队列的关系

ARCH-SEARCH 的探针代码与队列并行开发，不占用训练进程。
