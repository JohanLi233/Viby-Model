# 循环 CED 第二轮性能尝试（收尾记录）

用户要求尽快收尾，本轮不再扩大实验或启动训练。三个候选已实现，**均默认关闭**；
上一轮已启用的 CED 优化保持原设置。本轮没有新的已确认整模型提速结果。

| 候选 | 开关（默认 0） | 内容 |
|---|---|---|
| 稀疏 metadata 融合 | `VIBY_CED_METADATA_FUSION` | 一次整数 kernel 完成位置/doc/PAD 校验和索引压紧，保留选中集合与排序 |
| QB 阈值复用 | `VIBY_QB_THRESHOLD_REUSE` | 复用原生 argpartition；MLX 0.32.2 GPU 直接读取排序后的阈值，其余后端使用未选部分最大值 |
| mHC 训练融合 | `VIBY_HC_TRAIN_FUSION` | 融合系数生成与 Sinkhorn；保持 FP32 运算提升，支持实际 BF16/FP16 scale/base 及其梯度 |

QB 的版本限定来自 [MLX v0.32.2 Metal 源码](https://github.com/ml-explore/mlx/blob/v0.32.2/mlx/backend/metal/sort.cpp#L317-L339)：
该版本的 ArgPartition 使用完整排序。没有把这个实现细节当作跨版本 API 保证，也没有
改变原 argpartition 的调用或专家选择顺序。

实际检查：

- `tests/test_qb_threshold_reuse.py` + `tests/test_ced_metadata_fusion.py`：90 passed in 2.62s。
- `tests/test_hc_train_fusion.py`：16 passed in 2.80s，包含实际 BF16 模型转换后的 dispatch。
- metadata 为整数精确对拍，模型前向/路由输出相同；完整 BF16 反向使用 A/A 和全局
  梯度误差检查，不声称浮点原子归约后的参数梯度逐元素一致。

组件筛选只完成 `metadata_Q256`：原始配对耗时比 0.8262，但首尾 A/A 漂移 4.07%，
超过 3% 阈值，**不采用其表面提速作为确认收益**。随后 mHC 测量中检测到外部
GPU-capable 进程，独占守卫自动结束本实验，未终止其他任务。QB 组件计时和完整模型
窗口未执行；没有后台遗留的本轮测量进程。

- `experiments/bench_ced_pass2.py`：对照当前已优化 CED 的完整窗口测试，附进程冲突检测。
